Instructions

Screen-reader friendly shell, optional natural-language commands via Ollama, and how to run on Windows or Linux.

← Back to terminal

Console modes

Under Settings → Console mode, or the menu:

  • Accessible (default) — path, output, and command field. Best for structured screen-reader reading and natural language.
  • Full console — real terminal grid (xterm.js + node-pty). Best match for Linux/PowerShell commands, pipes, vim, and interactive programs. Open Full console. Use the accessible buffer to read output as plain text.

Accessible terminal overview

The accessible terminal page has three regions:

  • Current path — where you are in the filesystem
  • Output — read-only history of commands and results
  • Command — a text field to type shell commands (or natural language if enabled)

On Windows the shell is PowerShell. On Linux/macOS it is your default shell (usually bash or zsh).

Keyboard tips (accessible mode)

  • Enter runs the command (or sends input while a command is running)
  • Ctrl+C or Stop sends an interrupt
  • Tab completes paths and commands
  • Alt+F2 or Alt+O focuses output
  • Alt+C focuses the command field

Full console and accessible buffer

The Full console is a real terminal (xterm.js) with screenReaderMode enabled. It talks to a real shell over a TTY, so Linux tools, pipes, and interactive programs behave as they would in a normal terminal. That is why many users find it more capable for day-to-day shell work than the form-style Accessible page.

Use the accessible buffer when you want a stable, read-only snapshot of the terminal as plain text (similar in spirit to VS Code’s accessible terminal view).

Open the accessible buffer

  • Alt+F2 — open (or refresh if already open)
  • Or click Accessible buffer (Alt+F2) in the toolbar

While the buffer is open

  • Escape or Close — return to the full console and restore focus to xterm
  • Refresh snapshot or Alt+F2 again — update the text from the live terminal
  • Previous line / Next line buttons — move by line and announce the line
  • Ctrl+Up / Ctrl+Down — same as Previous/Next line (preferred; Alt+Arrow is often taken by the desktop or screen reader)
  • Alt+P / Alt+N — previous / next line (alternative)

Prefer Accessible terminal for natural language and simple structured output. Prefer Full console when you need a true Linux/PowerShell TTY, then Alt+F2 to read the result.

Natural language shell (nlsh) and Ollama

When enabled, you can type everyday language in the Accessible command box. The app asks local Ollama for a shell command, shows a confirmation dialog, then runs it if you accept.

Settings: enable and choose a model

  1. Open Settings.
  2. Enable natural language commands and choose an Ollama model (or pull one).
  3. Return to the Accessible terminal.

Ports

  • Web app — port 3000
  • Ollama — port 11434

Where to run the app and Ollama

See Settings for OS-specific install hints. Summary:

ollama pull llama3.2
npm run dev

Open http://localhost:3000. Optional CLI: npm run nlsh.

Troubleshooting

  • Port 3000 in use — stop the old process or use PORT=3001 npm run dev.
  • No models — install Ollama, pull a model, then Refresh on Settings.
  • Alt+Up/Down does nothing in the buffer — use Ctrl+Up/Down or the Previous/Next line buttons.
  • Full console hard to read — press Alt+F2 for the accessible buffer.
