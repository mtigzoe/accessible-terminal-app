Instructions

Screen-reader friendly shell, optional natural-language commands via Ollama, and how to run on Windows or Linux.

← Back to terminal

Console modes

Under Settings → Console mode, or the menu:

  • Accessible (default) — path, output, and command field. Best for screen readers. Supports natural language when nlsh is enabled.
  • Full console — real terminal grid (xterm.js) for vim and interactive programs. Open Full console. Natural language is not applied here. Use the accessible buffer (below) to read output more reliably with a screen reader.

Accessible terminal overview

The accessible terminal page has three regions:

  • Current path — where you are in the filesystem
  • Output — read-only history of commands and results
  • Command — a text field to type shell commands (or natural language if enabled)

On Windows the shell is PowerShell. On Linux/macOS it is your default shell (usually bash or zsh).

Keyboard tips (accessible mode)

  • Enter runs the command (or sends input while a command is running)
  • Ctrl+C or Stop sends an interrupt
  • Tab completes paths and commands
  • Alt+F2 or Alt+O focuses output
  • Alt+C focuses the command field

Full console and accessible buffer

The Full console is a real terminal (xterm.js) with screenReaderMode enabled. That helps, but a character grid is still harder for screen readers than a normal text field—especially after long output or in programs like vim.

Use the accessible buffer when you want a stable, read-only snapshot of the terminal as plain text (similar in spirit to VS Code’s accessible terminal view).

Open the accessible buffer

  • Alt+F2 — open (or refresh if already open)
  • Or click Accessible buffer (Alt+F2) in the toolbar

The dialog shows a read-only text area with the current scrollback. Focus moves there so you can use browse mode or the virtual cursor like any other document.

While the buffer is open

  • Escape or Close — return to the full console and restore focus to xterm
  • Refresh snapshot or Alt+F2 again — update the text from the live terminal
  • Alt+Up / Alt+Down — move by line and announce the line number and contents

Prefer the Accessible terminal for everyday commands and natural language. Use Full console when you need a true TTY (vim, interactive tools), then Alt+F2 to read the result.

Natural language shell (nlsh) and Ollama

When enabled, you can type everyday language in the Accessible command box (for example, “Where am I in this path”). The app asks local Ollama for a shell command, shows a confirmation dialog, then runs the command if you accept.

Settings: enable and choose a model

  1. Open Settings.
  2. Under Natural language shell (nlsh / Ollama), check Enable natural language commands in the web terminal.
  3. Under Model selection, open the Ollama model list and choose a model (for example llama3.2). Use Refresh model list if you just installed a model.
  4. Return to the Accessible terminal and type natural language or normal shell commands.

The selected model is stored in this browser. The standalone CLI (npm run nlsh) is separate and uses its own model via .env or !model.

Ports

  • Web app — port 3000 (open http://localhost:3000)
  • Ollama — port 11434 (the Node server talks to Ollama; the browser does not)

These ports do not conflict. You can run both at the same time.

Where to run the app and Ollama

The shell runs on the same machine as npm run dev. Ollama can be on the same machine or another host. Configure with the OLLAMA_HOST environment variable (default http://127.0.0.1:11434).

Option 1 — Everything on Windows (no Linux)

  1. Install Ollama for Windows and pull a model:
ollama pull llama3.2
  1. In the project folder, start the app (defaults are fine):
npm run dev

Open http://localhost:3000. In Settings, enable nlsh and select your model.

Option 2 — Everything on Linux

ollama pull llama3.2
npm run dev

Open http://localhost:3000 (or use VS Code Remote-SSH port forward and open http://localhost:3000 on Windows).

Option 3 — App on Windows, Ollama on Linux

On Linux, let Ollama accept network connections (if needed):

export OLLAMA_HOST=0.0.0.0:11434
ollama serve

On Windows, point the app at the Linux machine (replace the IP):

$env:OLLAMA_HOST = "http://192.168.1.50:11434"
npm run dev

Or keep Ollama on Linux localhost and tunnel port 11434 with SSH:

ssh -L 11434:127.0.0.1:11434 user@linux-host

Then on Windows use the default (no OLLAMA_HOST needed) and run npm run dev.

Standalone natural-language CLI

Optional command-line tool (same Ollama models):

npm run nlsh

Use !model to pick a model, !help for commands, exit to quit.

You can also start the CLI from another directory:

# Linux / macOS — adjust the path to your clone
npx --prefix ~/ai_shell/accessible-terminal-app ts-node \
  ~/ai_shell/accessible-terminal-app/src/nlsh.ts

Troubleshooting

  • Port 3000 already in use — stop the old server (fuser -k 3000/tcp on Linux, or end the Node process in Task Manager on Windows), or run PORT=3001 npm run dev.
  • Settings cannot list models — ensure Ollama is running and reachable from the machine that runs Node; click Refresh model list.
  • Natural language does nothing — use the Accessible terminal (not Full console), enable nlsh in Settings, and select a model.
  • Stuck on “Waiting for shell prompt” — on Linux the UI should detect bash prompts or enable after a few seconds; refresh the page after updating the app.
  • Full console is hard to read with a screen reader — press Alt+F2 for the accessible buffer, or switch to the Accessible terminal for line-oriented work.
